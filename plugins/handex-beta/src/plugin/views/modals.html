Tipo de especificação

Como funcionam as Tags

Cada especificação recebe uma Tag (A, B, C…) que define o grupo ao qual pertence no canvas. Use a mesma tag para specs relacionadas ao mesmo elemento ou contexto.

A

Mesma tag — ao criar, a spec fica solta no canvas para você arrastar para onde quiser. Ao clicar em Concluir posicionamento, ela se junta ao grupo da tag, na direção do lado escolhido (topo empilha para cima; demais lados empilham para baixo).

A B

Tags diferentes — grupos aparecem lado a lado no canvas, sem sobreposição.

Renomear grupo — clique no ícone de lápis ao lado do nome do grupo na lista de specs para personalizar o rótulo.

Controles do grupo

Na lista de specs, o cabeçalho de cada grupo (tag) tem botões para organizar o que aparece no canvas.

Ocultar linhas — esconde os conectores entre o grupo e o elemento no canvas, sem esconder as specs.

Ocultar grupo — esconde todas as specs daquela tag no canvas, sem apagar nada.

Cadeado — trava a posição de uma spec (ou do grupo inteiro) no canvas, para não mover sem querer.

Tipos de especificação

A cor do card no canvas reflete o tipo escolhido. Cada tom tem uma semântica intencional.

Informação extra

Descrição: Informações que não se encaixam nos demais tipos — pendências, decisões de reunião ou contexto adicional.

Exemplo: Alertas, observações, pendências, componente legado ou fora do DSC.

Comportamento

Descrição: Reação do sistema às ações do usuário além do padrão do DSC — microinterações, abertura de modais, transições de estado.

Exemplo: Sequência de ações, comportamento contextual da jornada, estado condicional.

Regra de Negócio

Descrição: Lógica do sistema não visível na interface — campos obrigatórios, validações e restrições de ações.

Exemplo: Campos obrigatórios, combinações válidas/inválidas, processos condicionais.

Dados da API

Descrição: Informações técnicas para integração com o backend — endpoints, campos esperados, estados de carregamento.

Exemplo: Tela dependente de resposta de API, dados mockados, informações temporárias.

Layout

Descrição: Grids, margens, alinhamentos e estruturas de containers — o esqueleto espacial da tela.

Exemplo: Espaçamentos, breakpoints, max-width, colunas de grid.

Componente

Descrição: Variações, estados e comportamentos de componentes do DSC específicos ao contexto documentado.

Exemplo: Estado disabled, variante outline, uso condicional de Badge, slot opcional.

Interação

Descrição: Fluxos de navegação e gestos do usuário — o que acontece quando o dedo toca a tela.

Exemplo: Swipes, taps, navegação entre telas, gestos de confirmação.

Tipografia

Descrição: Especificações de fontes, tamanhos, pesos e estilos tipográficos aplicados no contexto.

Exemplo: Heading-1, body-small, uso de itálico, truncamento de texto longo.

Cor

Descrição: Tokens de cor, paleta aplicada, contrastes e variáveis de cor do DSC.

Exemplo: color-primary-500, uso de surface-inverse, cor de fundo condicional.

Acessibilidade

Descrição: Notas sobre contraste, áreas de toque mínimas e leitura por leitores de tela.

Exemplo: Alt-text, hierarquia de cabeçalhos, focus states, ratio de contraste.

Conteúdo

Descrição: Textos, labels, mensagens e hierarquia de conteúdo da interface.

Exemplo: Placeholder, limite de caracteres, microcopy de botão, mensagem de estado vazio.

Entendendo as categorias

Especificar para leitores de tela consiste em definir como as tecnologias assistivas (como NVDA, Jaws ou VoiceOver) interpretam e anunciam os elementos da interface — orientações fundamentais pro time de desenvolvimento implementar a experiência exatamente como projetada.

Estrutura da página

São elementos semânticos que estruturam o "esqueleto" de uma página, indicando as seções de conteúdo e para que servem. Exemplo: <header>, <main>, <footer>, etc. Listas também estão incluídas.

H

Nível de título (heading)

Cabeçalhos (H1-H6) estruturam a página logicamente. O H1 é o título principal (único por página), seguido por H2, H3 e assim por diante. Essa ordem permite que usuários de leitores de tela entendam o sumário do conteúdo. No mobile (React Native), essa semântica de nível não existe — use o marcador único "H".

A

Elementos interativos e imagens

Elementos interativos (como botões e links) executam ações. Se usam apenas ícones, necessitam de texto alternativo que descreva sua função (ex: "buscar") e não a aparência ("Lupa"). Para imagens estáticas, também use esse grupo.

Elemento decorativo

Elementos decorativos são itens visuais que não transmitem conteúdo ou função, como divisores, formas abstratas ou ícones redundantes. Eles devem ser ignorados por leitores de tela para evitar ruídos desnecessários.

Informações adicionais

Caso queira contemplar algum elemento/componente que não se encaixa nas outras categorias, use esta pra descrever o item e apontar suas observações — é a única categoria com formato livre.

Estrutura padrão de cada spec

Toda categoria segue os mesmos campos — Descrição (como o elemento deve ou não ser lido) e Notas de Código (apontamento técnico pro dev), quando aplicável à variante escolhida.

Área → Especificação

Marcar Área (selo azul numerado) é o pré-requisito: identifica uma seção ou bloco da tela e agrupa, na listagem lateral, todas as especificações criadas dentro dela. Cada uma das 5 categorias acima é uma Especificação, sempre criada dentro de uma área já marcada.

Contorno (padrão) envolve o elemento inteiro com uma moldura, com o selo embutido num dos cantos. Linha liga um ponto do elemento ao card de detalhamento com um traço, sem contornar a área — útil quando o elemento é pequeno ou está muito próximo de outros.

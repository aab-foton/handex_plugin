Proposta: Handoff Completo sem Auto Layout consolidado

Ao estudar a complexidade do Handoff Completo junto com o time da vertical, ficou claro que a forma como os 4 blocos (Tabulação, Swipe, Leitor de Tela, Consolidado) são hoje reunidos num único frame — o que atrapalha a posição dos marcadores e a estruturação geral do handoff. Este documento propõe uma arquitetura alternativa que resolve a causa raiz identificada, mantendo a experiência visual atual (tudo lado a lado, em sequência).

⏳ Decisão pendente — este documento é insumo para alinhamento com a vertical de Acessibilidade, não uma mudança já aprovada ou implementada.

1. O que existe hoje

Cada área marcada tem um "Handoff Completo" — um frame que reúne até 4 blocos lado a lado: Tabulação, Swipe (só mobile), Leitor de Tela e Consolidado. Esse frame usa Auto Layout horizontal, e cada um dos 3 primeiros blocos, por dentro, também tem Auto Layout — contendo uma coluna de legenda, mais uma réplica (clone) da tela original, mais um grupo de marcadores (selos numerados, trilha de swipe, ou specs de leitor de tela) sobreposto à réplica.

Legendainstrução do bloco
Cloneréplica da telaAuto Layout: recalcula posição
Overlayselos/trilha/specsprecisa compensação manual

↑ 1 bloco (ex. Tabulação) dentro do frame consolidado — os 3 filhos vivem dentro de um Auto Layout HORIZONTAL, que por sua vez é filho do Auto Layout do frame "Handoff Completo" inteiro.

Para que o marcador fique visualmente sobreposto à réplica (e não empurrado para o lado, como faria um item comum de Auto Layout), o grupo de marcadores é retirado do fluxo do Auto Layout (layoutPositioning: 'ABSOLUTE'). Isso funciona bem enquanto nada muda de posição — mas cada vez que a réplica é movida (por exemplo, ao inserir o bloco dentro do Handoff Completo), o Figma recalcula automaticamente a posição dela para caber no Auto Layout, e o marcador — que não faz mais parte desse recálculo — pode ficar dessincronizado.

2. Diagnóstico — de onde vem a complexidade

A causa raiz não é o modelo "réplica + marcadores sobrepostos" em si — esse modelo já existe e funciona bem em outras partes do plugin (na área de trabalho normal, antes de qualquer coisa entrar no Handoff Completo). A causa raiz é colocar essa combinação para conviver dentro de um Auto Layout automático, que tenta reorganizar tudo sozinho sempre que algo muda de tamanho ou de posição.

Sempre que o Figma recalcula a posição da réplica automaticamente (porque ela é filha de um Auto Layout), o grupo de marcadores — que precisa ficar "congelado" fora desse fluxo — corre o risco de ficar para trás, gerando exatamente os sintomas relatados: marcadores fora do lugar, vazando da área visível, ou (num bug histórico já corrigido) fazendo o bloco inteiro esticar para milhares de pixels de largura.

4. A proposta

Manter tudo lado a lado, na mesma ordem visual de hoje — só trocar quem calcula a posição de cada bloco: em vez do Figma decidir sozinho (Auto Layout), o próprio plugin calcula e posiciona cada bloco explicitamente.

Tabulaçãoframe soltoposição calculada pelo plugin
Swipeframe soltoposição calculada pelo plugin
Leitor de Telaframe soltoposição calculada pelo plugin
Consolidadoframe soltoposição calculada pelo plugin

↑ Os 4 blocos continuam visualmente lado a lado, dentro de uma mesma área agrupadora — mas nenhum deles é filho de um Auto Layout que os force a conviver. Cada bloco mantém seu próprio Auto Layout interno (isso nunca foi o problema).

  1. Cada bloco vira um frame independente, agrupado visualmente dentro de uma área do canvas dedicada ao Handoff Completo daquela tela — sem um "frame-mãe" com Auto Layout amarrando os 4 juntos.
  2. O plugin calcula a posição de cada bloco toda vez que algo é inserido ou atualizado — o mesmo espaçamento visual de hoje, só que decidido pelo código em vez de pelo Figma. Isso já é o mesmo princípio usado hoje para garantir a ORDEM correta dos blocos (Tabulação sempre primeiro, depois Swipe, etc.) — a proposta estende esse princípio também para a POSIÇÃO.
  3. Deixa de ser necessário "congelar" o marcador fora de um fluxo automático — como a réplica nunca mais é filha de um Auto Layout, sua posição não é mais recalculada sozinha pelo Figma, e o marcador continua exatamente onde deveria, sem nenhuma compensação manual extra.
  4. "Ver handoff no canvas" continua funcionando igual — em vez de levar a 1 frame único, passa a selecionar os 4 blocos de uma vez e ajustar o zoom para mostrar todos — o efeito para quem usa o plugin é o mesmo (um clique, tudo aparece enquadrado).
  5. Nada muda no painel de status (a aba "Handoff" com os indicadores de cada etapa) nem na detecção de "desatualizado" — esses já funcionam de forma independente de onde as coisas estão fisicamente no canvas.

5. O que a proposta preserva

  • A visão de conjunto — tudo lado a lado, sequencial, sem precisar caçar blocos espalhados pelo canvas.
  • O modelo de 1 réplica de trabalho por tipo por área, reaproveitada e editada incrementalmente (nunca "réplica da réplica").
  • A ordem fixa dos 4 blocos (Tabulação → Swipe → Leitor de Tela → Consolidado).
  • Tudo que já funciona hoje no dashboard, nos textos de instrução, e nos próprios marcadores em si — a proposta muda só a forma como os blocos se posicionam uns em relação aos outros.

6. Trade-off

Ganho

  • Elimina a causa raiz das 2 rodadas de bug mais recentes e mais visíveis (ambas reportadas nesta mesma semana).
  • Simplifica o código que move a réplica para dentro do Handoff Completo — não precisa mais medir/compensar deslocamento.
  • Reduz a dependência de "adivinhar" como o Figma vai reorganizar automaticamente algo — mais previsível, mais fácil de testar.

Custo

  • O plugin passa a ser responsável por recalcular manualmente a posição dos blocos sempre que um deles muda de tamanho (ex.: uma tela mais alta documentada faz o bloco de Tabulação crescer) — algo que o Auto Layout fazia de graça.
  • Esse recálculo, se mal feito, poderia introduzir uma nova categoria de bug (posições desatualizadas depois que um bloco cresce) — mitigado reposicionando tudo do zero a cada atualização, nunca de forma incremental.

Importante: esta proposta não promete eliminar todo o histórico de bugs desta área — as 8 rodadas "inerentes ao modelo" (seção 3) continuam sendo tratadas do mesmo jeito que hoje, com as correções já aplicadas. O ganho real é eliminar especificamente a fonte mais recente e mais visível de instabilidade.

7. Próximos passos

Este documento é insumo para uma conversa, não uma decisão fechada. Pontos a alinhar com a vertical antes de qualquer implementação:

  • Confirmar se a leitura de "o problema é o Auto Layout consolidado" bate com a percepção do time ao usar a Ficha no dia a dia.
  • Validar se o efeito visual proposto (blocos soltos, mas visualmente equivalentes a hoje) atende, ou se há alguma expectativa específica de comportamento do Auto Layout que a vertical valoriza e que esta proposta não cobriu.
  • Definir prioridade — esta é uma mudança estrutural, não um bug pontual; vale decidir se entra numa próxima rodada de manutenção ou se aguarda um momento mais tranquilo do roadmap.

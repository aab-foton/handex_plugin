Design System do Handex

O que é esta página: referência viva do design system da interface do próprio plugin Handex — não o DSC (Design System CAIXA), que é o sistema externo auditado pelo plugin. Cada componente abaixo é renderizado com o CSS real do Handex (cores, fontes, radius, espaçamentos idênticos ao código-fonte), não apenas descrito em texto.

Como usar: antes de criar uma tela, botão ou card novo, confira aqui o padrão já existente. Toda cor/tamanho/componente citado tem uma referência de arquivo:linha entre parênteses — se o código atual divergir do que está aqui, é dívida técnica (seção 7), não uma segunda opção válida.

Escopo desta versão: cobre os padrões estruturais reutilizados entre as 6 ferramentas do plugin (Guia, Dados do Projeto, Escanear Tokens/Handoff, Anotar Specs, Anotar Medidas, Fluxos de Tela) — não cobre elementos gerados no canvas do Figma (specCard, conectores), que seguem a Plugin API e estão documentados inline em code.js.

Arquivo local autocontido, versionado no repositório — não é publicado como site (sem GitHub/GitLab Pages, sem hospedagem externa). Funciona abrindo direto no navegador (file://), sem instalar nada e sem CDN externo obrigatório.

2. Tipografia

Fonte única: Inter, sans-serif (plugin.css:3), forçada com !important em headings/labels/pills (plugin.css:497-501). Escala confirmada via varredura de text-[Npx] em todo o código (contagem real de ocorrências entre parênteses).

Título de destaque — 22px extrabold (4 ocorrências)

Título de modal grande / header de view — 18px bold (15 ocorrências)

Título de modal médio — 15–16px extrabold (4 ocorrências)

Título de modal pequeno — 14px bold (10 ocorrências)

Corpo de botão / título de card — 13px (29 ocorrências)

Texto de card padrão / body — 12px (163 ocorrências — o tamanho mais usado no plugin)

Subtítulo de header / label de modal — 11px (196 ocorrências)

Hints, descrição de card, badge — 10px (223 ocorrências)

Contador de caractere, uppercase pill — 9px (166 ocorrências)

Menor tamanho em uso — 8px (36 ocorrências)

Pesos: font-bold é o padrão de botão/label; font-extrabold reservado a títulos de destaque e CTAs primários; font-semibold/font-medium para ênfase secundária.

Os tokens nomeados text-3xs/text-2xs/text-xs-plus/text-md ainda não existem em fontSize do tailwind.config.cjs — o código inteiro usa valores px arbitrários (text-[10px] etc.) em vez de nome de classe. Os valores acima são os corretos, só não têm nome de token ainda.

5. Componentes

Botões — catálogo de 6 variantes

Fonte: varredura de classes literais em views/*.html. Todo botão do Handex é uma destas 6 variantes.

Primária: bg-blue-500 hover:bg-blue-600 text-white rounded-2xl font-bold. Destrutiva: bg-red-500 hover:bg-red-600. Branco/outline neutro: bg-white border border-gray-200 rounded-2xl py-3 text-[12px] font-bold (dimensão única desde 2026-08-26). Sub-variante link externo: mesma dimensão, borda/texto blue-500. Disabled (todas as variantes): disabled:opacity-40 disabled:cursor-not-allowed, nunca troca a cor de fundo.
Secundária/ghost sobre header azul: fundo bg-white/10, hover:bg-white/20. Botão-ícone interativo isolado: container w-10 h-10 (40×40px de área de toque real).
Ícone utilitário com fundo: bg-white border border-gray-200 rounded-2xl, cor de hover semântica (vermelho para descarte).
Divergência confirmada: home.html:167 e 3 ocorrências em modals.html (linhas 102, 1006, 1247) ainda usam hover:bg-[#004d8f]/hover:bg-[#005a8e] — hex do azul institucional pré-reversão de marca, não a classe nomeada hover:bg-blue-600 atual. Essas 4 ocorrências não foram migradas.

Implementado via classe dark na raiz (Tailwind darkMode: 'class', tailwind.config.cjs:3) — todo componente do plugin declara o par bg-light-* dark:bg-dark-* lado a lado.

Contraste WCAG 2.1 AA — auditoria de 2026-08-26 (piso: texto normal 4.5:1, texto grande/ícone 3:1): confirmadas e corrigidas 14 reprovações (opacidade de texto branco sobre header azul, dark: ausente em textos azuis, badges de categoria, texto secundário direto sobre fundo de view). 7. Dívida técnica observada (código vs. padrão declarado)

Itens confirmados por leitura direta do código nesta revisão — cada um é uma correção pontual, não um redesenho:

  1. 3 paletas de categoria de spec não convergidas — Ficha exportada (handoff.js:736-741), card do canvas (_CAT_COLORS, specifications.js:463-468) e legenda do modal de ajuda (modals.html:396-418) usam 3 conjuntos de hex diferentes para as mesmas 4 categorias.
  2. Bug adormecido de verde/laranja — plugin.css:127-134 faz button.bg-green-600/.bg-green-500 herdar #935300 (cor de hover do laranja de alerta). Confirmado ainda presente no código.
  3. rounded-xl não é residual — 141 ocorrências reais em views/*.html, incluindo o botão "voltar" do header padrão de toda view. O padrão declarado (rounded-2xl universal) e o uso real convivem sem terem convergido.
  4. Radius de card via seletor de atributo global — [id$="-card"] { border-radius: 16px !important } (plugin.css:451-465) em vez de classe Tailwind direta no elemento. Confirmado ativo.
  5. z-index de modal sem constante nomeada — z-[1000]/z-[1200]/z-[200] continuam valores mágicos espalhados no HTML.
  6. Hex de brand direto no HTML — 4 ocorrências confirmadas de hover:bg-[#004d8f]/hover:bg-[#005a8e] (hex pré-reversão de marca) em home.html:167 e modals.html:102,1006,1247, além de uso disseminado de bg-[#005ca9] em vez de bg-blue-500 em muitas outras views.
  7. Escala tipográfica sem token nomeado — text-3xs/text-2xs/text-xs-plus/text-md não existem em fontSize do tailwind.config.cjs; todo o código usa px arbitrário.
  8. 4 dialetos de accordion — toggleAccordion(btn, nodeId) (core.js:2696) é o padrão oficial, mas guide.html (onclick inline sem aria-expanded), o Briefing Estratégico (div role="button") e chevrons próprios (.journey-chevron, .group-chevron) ainda coexistem.
  9. Contadores de caractere abaixo do piso de contraste — text-[9px] text-slate-400 sobre card branco mede ~2.6:1 (piso é 4.5:1), ~20 ocorrências, registrado como pendência e não corrigido em massa.
  10. Nomenclatura de tela inconsistente — card na home diz "Escanear Tokens", id interno é view-frames, arquivo é handoff.html; nome canônico proposto é "Handoff", ainda não convergido nas 3 pontas.

Arquivos-fonte consultados nesta revisão: src/plugin/styles/{tailwind.config.cjs,plugin.css}, src/plugin/modules/{core,handoff,specifications,measurement,briefing}.js, src/plugin/views/{home,specifications,modals,dados-projeto}.html. Última verificação de código: 2026-09-02.

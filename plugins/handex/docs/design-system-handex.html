Design System do Handex

Catálogo de tokens e componentes da interface do próprio plugin Handex. Toda nova tela ou variante visual segue o que está definido aqui — onde o código atual diverge, é dívida técnica a corrigir, não uma segunda opção válida.

Escopo: isto é o design system do plugin — a linguagem visual da ferramenta que a Fóton usa para documentar handoff. Não confundir com o DSC (Design System Corporativo da CAIXA), que é o design system externo que o Handex audita e referencia nos scans de conformidade.
Como ler este documento: selo Canônico marca o padrão a seguir. Selo Migrar marca uso legado que ainda existe no código mas não deve ser replicado em telas novas — ver seção "Dívida técnica" para a lista completa com localização.

Botões 05

6 variantes cobrem todo botão do Handex. Não criar uma 7ª sem atualizar este catálogo primeiro.

Primária

Canônico

bg-blue-500 hover:bg-blue-600 text-white rounded-2xl font-bold — ação de fluxo/confirmação.

Secundária / ghost (sobre header)

Canônico

Ação alternativa dentro do header azul — fundo transparente ou bg-white/10, hover:bg-white/20, mesmo radius da primária.

Branco / outline neutro

Canônico

Ação secundária com texto fora do header — py-3 text-[12px] font-bold, borda cinza. Sub-variante link externo: mesma dimensão, borda/texto na cor de marca quando leva a um destino fora do plugin (ex: site do DSC).

Destrutiva

Canônico

bg-red-500 hover:bg-red-600 text-white rounded-2xl font-bold — ação irreversível (excluir, limpar dados).

Ícone interativo

Canônico

Container w-10 h-10 flex items-center justify-center rounded-2xl — área de toque real 40×40px, glifo interno visível e proporcional (não reduzido a uma hit-area invisível). Botões-ícone adjacentes usam o gap do container flex — nunca margem negativa nos dois lados de botões vizinhos.

Ícone utilitário com fundo

Canônico

Ação secundária de rodapé/lista, só ícone sem texto (download, lixeira) — fundo bg-white/dark:bg-dark-surface com borda, cor de hover semântica.

Estado disabled

Canônico — todas as variantes

disabled:opacity-40 disabled:cursor-not-allowed — regra única para qualquer cor de botão. Não trocar o fundo por cinza sólido.

Fora deste catálogo, por serem estruturalmente diferentes de um botão de texto linear: os cards seletores de opção em grid (ex: modal de medidas — ícone grande + label embaixo, border-2) não seguem esta padronização; são um componente de seleção visual, não uma ação.

Accordions 06

toggleAccordion(btn, nodeId) é o único padrão oficial. Sempre seta aria-expanded; nodeId habilita exclusividade entre irmãos quando aplicável. Estado inicial padrão: fechado, salvo decisão explícita de UX para a tela (ex.: Briefing Estratégico nasce aberto).

toggleAccordion() — padrão único

Canônico
Regras e Histórias de Usuário ⌄

Migrar

Toggles 08

O switch estilizado é o padrão oficial para escolha binária habilitado/desabilitado. Checkbox nativo continua correto para seleção múltipla em listas — são componentes com papéis diferentes, não uma substituição 1:1.

Switch estilizado

Canônico — liga/desliga

Padrão oficial para qualquer escolha binária habilitado/desabilitado em telas novas.

Checkbox com accent

Canônico — seleção múltipla

Correto para seleção múltipla (import/limpeza de dados) — não para toggle liga/desliga.

Nomenclatura de tela 11

A tela hoje referenciada por 3 nomes diferentes tem nome canônico definido — reflete o papel real da tela, não só a ação de escanear.

Hub de frame

Canônico: "Handoff"

Card na home diz "Escanear Tokens", id é view-frames, arquivo é handoff.html — "Handoff" é o nome que reflete o papel real da tela (scan + medidas + specs + conformidade). Card na home, título interno e documentação devem convergir para este nome (Dívida técnica, item 9).

Como usar o plugin

O Handex organiza toda a documentação de handoff em ferramentas independentes. Use cada uma no momento certo — não precisa seguir uma ordem. Quando tudo estiver pronto, gere a Ficha de Handoff no canvas.

Registra o contexto do que está sendo entregue — título, objetivo, equipe responsável e, dentro de Contexto de Negócio, o briefing estratégico, as regras de negócio/HUs e os links de referência. Esse contexto aparece no topo da ficha final, para o dev entender o "porquê" da entrega antes de mergulhar no "como" — sem precisar te perguntar no Slack ou adivinhar pelo protótipo.

  1. 1Clique em Informações do Projeto na home — o modal abre sobre qualquer tela, sem precisar sair do que está fazendo.
  2. 2Preencha Título, Versão e Objetivo — esses três campos são obrigatórios para gerar a ficha.
  3. 3Adicione ao menos 1 membro de equipe com nome preenchido — sem isso o botão de gerar ficha fica bloqueado. O e-mail é opcional.
  4. 4As três seções de Contexto de Negócio são opcionais e vêm ativadas por padrão — cada uma tem seu próprio toggle no cabeçalho: desativar esconde a seção sem apagar nada já preenchido, útil quando ela não se aplica a este projeto.
  5. 5Briefing Estratégico: perguntas de negócio organizadas em 5 eixos (Contexto do Projeto, Escopo e Riscos, Usuários e Stakeholders, UX e Design, Pesquisa e Evidências) — o lugar de registrar o "porquê" da entrega, decisões de escopo e riscos conhecidos, para o dev não perder esse contexto quando o design já estiver pronto. Use o ícone ? para abrir o Guia e inserir perguntas sugeridas com um clique; o menu ⋮ reúne baixar template em branco, importar/exportar em .md e limpar tudo.
  6. 6Regras de Negócio e HUs: lógica que não aparece no design em si — campos obrigatórios, validações, condições de exibição, histórias de usuário vinculadas. Sem isso documentado, o dev tem que adivinhar essas regras só olhando a tela ou te interromper para perguntar.
  7. 7Links de Referência: URLs de Protótipo Navegável, Handoff de Acessibilidade e Pesquisa de UX — cada um vira um link clicável direto na ficha final, levando o dev para a fonte original sem precisar pedir de novo.
  8. 8Tudo é salvo automaticamente a cada alteração — o botão Salvar e Voltar no rodapé é só um atalho para voltar à home, não é preciso clicar nele para não perder o que preencheu.

Não é uma leitura automática que basta rodar uma vez: o scan traz cores, tipografia, componentes e vetores do frame, já com um batimento automático contra o Design System CAIXA — mas o critério é exigente. Sem token vinculado, o item conta como fora do padrão, sem meio-termo. Cabe a você revisar cada caso, como no Check Designs nativo do Figma, e decidir: ajustar o elemento ou justificar o desvio por escrito. Quando o frame traz um componente inédito, ainda fora do DSC, a ferramenta registra as propriedades dele como referência para uma futura incorporação.

  1. 1Com esta ferramenta aberta, selecione um Frame (ou Componente, Seção, Grupo) no canvas do Figma.
  2. 2Clique em + Registrar Frame — o plugin captura o ID e o nome do elemento selecionado, cria um card e escaneia automaticamente Componentes, Ícones, Tipografia e Vetores.
  3. 3O resultado aparece agrupado por tipo em Tokens Escaneados, já com o batimento automático: cada item mostra "Em conformidade", "Necessita revisão" ou "Fora do padrão", com a contagem de propriedades em cada status. Este é o passo que exige sua revisão: expanda cada item para ver o token aplicado (trilha completa, ex: cor › primária › 500) e clique nele para focar o elemento correspondente no canvas e confirmar visualmente se o vínculo faz sentido.
  4. 4Se algum item não tem token vinculado, ele aparece destacado. O painel "Itens para revisar", no topo do card, reúne todos esses casos num só lugar — clique em qualquer um para ir direto ao elemento.
  5. 5Mudou algo no frame depois do primeiro scan? O ícone de atualizar, ao lado de "Tokens Escaneados", re-escaneia a qualquer momento sem perder o que já foi declarado — o batimento automático não é ao vivo, só reflete o estado do Figma no momento em que você escaneou.
  6. 6Declare a Conformidade DSC: marque "Check Designs realizado" e informe se há desvios. O critério é rígido — um item sem token vinculado mantém o frame como "Não Conforme" (vermelho) mesmo que você marque "Sem desvios", até você escrever uma justificativa no campo de observações. Com a justificativa preenchida, o status passa para "Em revisão" (amarelo) — nunca vira "conforme" por omissão.
  7. 7Se o frame é um Novo Componente, ative o toggle — a seção de conformidade é ocultada (não se aplica a componentes inéditos) e o frame é destacado na ficha.
  8. 8Repita para cada frame do projeto. Você pode ter múltiplos frames documentados em paralelo.

Registra decisões técnicas específicas de um elemento — regra de negócio, comportamento, valor de token aplicado — que o scan automático não capta sozinho. É a camada de contexto que só o designer sabe explicar, ancorada visualmente no elemento certo do canvas.

  1. 1Selecione um elemento no canvas do Figma — pode ser um componente, texto, ícone ou qualquer elemento.
  2. 2Clique no botão + no topo da view de Especificações. O formulário abre com o elemento selecionado já vinculado (visível no topo, fixo durante toda a edição).
  3. 3Defina a Tag (referência do grupo, ex: A, B, A1, A1.1) e a Categoria: Informação extra, Comportamento, Regra de Negócio ou Dados da API — a cor do grupo é definida automaticamente pela categoria.
  4. 4Adicione uma Nota personalizada (opcional) e escolha se quer inserir linha de conexão no canvas — com estilo Reta ou Angular. Se quiser, ative Incluir link de referência e cole uma URL.
  5. 5Em Propriedades, marque os atributos técnicos identificados no scan (nome, token do Design System e valor aplicado) que fazem parte desta spec.
  6. 6Na etapa Posição no Canvas, um card fantasma (tamanho real, sem texto) já aparece posicionado ao lado do elemento, com zoom automático — arraste-o para onde quiser e clique em Usar esta posição. Não quer marcar agora? Clique em Pular e a spec nasce solta à direita do elemento; depois é só arrastar o card e usar Travar especificação no menu "..." para concluir. Mesma tag empilha verticalmente; tag diferente abre nova coluna.
  7. 7Para documentar cenários alternativos antes de concluir, use Cenário de Exceção — escolha Erro, Sucesso, Alerta ou Confirmação. Também dá pra adicionar exceções depois, expandindo a spec já criada na lista.
  8. 8No cabeçalho de cada grupo de tag você pode nomear o grupo (ex: "Grupo A — Botão Primário"), ocultar as linhas de conexão no canvas, ocultar o grupo inteiro da ficha, ou usar o cadeado para travar/destravar todas as specs do grupo de uma vez.

Dica: o scroll e o destaque no canvas só ocorrem ao expandir uma spec na lista — não ao passar o mouse.

Converte espaçamentos e dimensões do canvas em anotações visíveis — altura, largura, margens, paddings e gaps — para o dev implementar sem precisar inspecionar o Figma medida por medida.

  1. 1Selecione 1 ou mais elementos no canvas do Figma que você quer documentar dimensionalmente.
  2. 2Clique no botão + no topo da view de Medidas. Escolha ao menos um tipo:
W × H

Largura e altura do elemento

Margin

Espaçamento externo (outer)

Padding

Espaçamento interno

Spacing

Padding + gaps automáticos

  1. 3Confirme — as anotações são criadas no canvas do Figma e aparecem na lista do plugin com nome e valores.
  2. 4Use o botão Ocultar tudo para esconder temporariamente todas as medidas do canvas sem excluí-las.

Mapeia a navegação entre telas — sequências, decisões e eventos — para o dev enxergar a jornada completa antes de implementar cada tela isoladamente.

  1. 1Selecione 2 ou mais elementos no canvas e clique em + Conectar Frames. Com 3 ou mais, o plugin conecta em cadeia automaticamente (da esquerda para a direita).
  2. 2Nome da Jornada: o texto digitado nomeia o card que agrupa todas as conexões que se tocam na lista de Fluxos — não o nome de uma linha isolada. Se a seleção estender uma jornada já existente, deixe em branco para manter o nome atual.
  3. 3Marcar início e fim automaticamente (opcional, desmarcado por padrão): o primeiro elemento selecionado recebe o marcador de Início, o último recebe o de Fim.
  4. 4Escolha o tipo de conexão:
SequênciaTransição direta entre telas
MensagemEvento ou troca assíncrona
DecisãoLosango de bifurcação (obriga texto), só com 2 elementos
Decisão (Opcional)Condicional, também só com 2 elementos
  1. 5Quer ramificar uma decisão a partir de um card no meio de uma cadeia já criada (ex: A→B→C→D e quer decisão saindo de B)? Não dá na mesma operação — conecte esse card com o novo elemento separadamente, escolhendo Decisão. Alternativa: crie como Sequência dentro da cadeia e depois troque o tipo pra Decisão editando a conexão.
  2. 6No mini-mapa de ancoragem, clique numa borda de qualquer card para escolher, por card, o lado de onde a conexão sai — ele reflete a posição real dos elementos selecionados no canvas. O toggle Auto no header do mini-mapa limpa todas as escolhas manuais de uma vez.
  3. 7Estilo da linha: Reta ou Angular. Texto do chip/decisão tem limite de 20 caracteres (contador visível no campo).
  4. 8O fluxo é criado no canvas e aparece na lista. Clique no ícone de foco para focar na seta no canvas. Numa conexão já criada, o modal de edição também permite trocar o tipo (Sequência/Mensagem/Decisão/Decisão Opcional) sem apagar e reconectar.

Consolida tudo que foi documentado — specs, medidas, fluxos e conformidade com o DSC — num documento único e versionado no canvas, pronto para a entrega ao time de desenvolvimento.

  1. 1Verifique que os pré-requisitos estão preenchidos: título, objetivo, ao menos 1 membro de equipe com nome preenchido (e-mail é opcional).
  2. 2Clique em Gerar Ficha de Handoff na home para abrir a tela de resumo. Lá, clique em Gerar Ficha no topo (ou o mesmo botão dentro de Informações do Projeto). Se já existe uma ficha, o plugin pergunta se a nova versão é Minor (ajuste) ou Major (redesenho).
  3. 3A ficha é criada no canvas com o nome Handex | Ficha de Projeto | {Título} | {Data} e posicionada fora dos frames existentes.
  4. 4Na tela de resumo, você também pode exportar a documentação como Markdown (.md) ou JSON (.json) — útil para compartilhar com devs sem acesso ao Figma.
  5. 5A ficha é criada desbloqueada — você pode mover e organizar no canvas à vontade. Specs, medidas e fluxos individuais permanecem bloqueados.

Exportar

  1. →O botão Baixar, no rodapé da home, exporta o JSON completo a qualquer momento, sem precisar sair da tela em que você está.
  2. →Para exportar em Markdown, acesse Gerar Ficha de Handoff → use os botões de exportação na tela de resumo.
  3. →O JSON é a fonte completa de dados — contém specs, medidas, fluxos, propriedades e tokens escaneados. Ideal para integrações com outros sistemas.

Importar

  1. →Clique em Importar JSON na home e selecione um arquivo exportado anteriormente. O plugin restaura todos os dados e incrementa a versão automaticamente.
  2. →Após importar, escolha o que recriar no canvas: Ficha Técnica, Cards de Spec, Medidas e/ou Fluxos.
  3. →Fluxos só são recriáveis se o backup foi gerado nesta versão do plugin ou mais recente — backups mais antigos não salvavam o vínculo com os elementos conectados, e o fluxo aparece como não recriável.

Antes de apagar

  1. →O botão Baixar, no rodapé da home, exporta um backup completo em JSON a qualquer momento — recomendado antes de qualquer uma das ações abaixo, já que nenhuma delas pode ser desfeita. O mesmo botão também aparece no topo do modal de limpeza, como lembrete.

Apagar dados do plugin

  1. →Reseta o progresso salvo no Handex (frames registrados, specs, medidas e fluxos do hub). Não remove nada do canvas — só o que o plugin está rastreando internamente.

Apagar conteúdo do canvas

  1. →Remove de verdade os elementos que o Handex criou no canvas desta página — marque só o que quer apagar: Ficha de Handoff, Specs, Medidas e/ou Fluxos (ou "Selecionar tudo").
  2. →Se apagou algo por engano, um backup em JSON baixado antes permite trazer de volta via Importar JSON.

Documentação de Apoio

Algumas layers geradas pelo plugin são bloqueadas

Medidas e Fluxos são criados com bloqueio de edição para preservar a integridade do handoff. Specs nascem destravadas e podem ser bloqueadas manualmente pelo ícone de cadeado; a Ficha de Projeto também nasce destravada. Para remover qualquer item, use os botões de exclusão dentro do próprio plugin (ou "Apagar conteúdo do canvas", no ícone de lixeira da home).
